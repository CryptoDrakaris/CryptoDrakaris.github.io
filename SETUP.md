# Как поднять проект на другом компьютере

Сайт: https://cryptodrakaris.github.io/
Репозиторий: https://github.com/CryptoDrakaris/CryptoDrakaris.github.io

## Что нужно установить

| Программа | Версия | Где взять |
|---|---|---|
| Node.js | 22 или новее (проект собран на 22.23.2) | https://nodejs.org – кнопка LTS |
| Git | любая свежая | https://git-scm.com/downloads |

Больше ничего не нужно: ни ключей API, ни платных сервисов, ни Python.

Проверить после установки (в терминале):

```bash
node -v && npm -v && git --version
```

## Вариант 1. Через GitHub – рекомендую

Самый надёжный способ: код берётся из репозитория, ничего не зависит от синхронизации.

```bash
git clone https://github.com/CryptoDrakaris/CryptoDrakaris.github.io.git drakaris-site
cd drakaris-site
npm install
npm run dev
```

Откройте http://localhost:4321 – сайт работает локально.

При первом `git push` откроется окно входа в GitHub: войдите в свою учётную запись, дальше компьютер запомнит вход.

## Вариант 2. Через папку в Proton Drive

Папка `CLAUDE/LAZY_LIONS` синхронизируется целиком, поэтому на новом компьютере она появится сама. Нужно только:

```bash
cd "<путь к папке LAZY_LIONS>"
npm install
npm run dev
```

Дождитесь, пока Proton Drive закончит синхронизацию, прежде чем запускать сборку. Если во время работы появляются ошибки вида «файл занят» – поставьте синхронизацию на паузу.

## Что синхронизируется, а что восстанавливается

| Папка | Размер | Нужно ли синхронизировать |
|---|---|---|
| `src`, `scripts`, `data/collection.json`, `data/derived.json`, `public/derived` | ~50 МБ | да, это сам проект. Всё это есть и в репозитории |
| `node_modules` | ~236 МБ | **нет.** Восстанавливается командой `npm install` |
| `dist` | ~56 МБ | **нет.** Это результат сборки, создаётся командой `npm run build` |
| `data/originals` | ~335 МБ | **нет.** Оригиналы NFT, восстанавливаются командой `npm run fetch` |

Если Proton Drive умеет исключать папки, исключите `node_modules`, `dist` и `data/originals`: это уберёт больше 600 МБ и тысячи мелких файлов из синхронизации.

Важно: сайт собирается **без** оригиналов. Превью уже лежат в репозитории, поэтому `npm run build` работает сразу после `npm install`.

## Команды

```bash
npm run dev      # локальный просмотр: http://localhost:4321
npm run build    # собрать сайт в папку dist
npm run fetch    # перечитать кошелёк и скачать новые оригиналы (10-20 минут)
npm run derive   # сделать превью и акцентные цвета из оригиналов
npm run archive  # личный архив: оригиналы со всех сетей на диск, на сайт не попадают
```

Проверка доступности перед публикацией (нужны зависимости проекта, ставятся через `npm install`):

```bash
node .claude/skills/web-design-audit/scripts/axe-static.mjs dist --limit 600
```

## Личный архив по всем сетям

`npm run archive` скачивает оригиналы NFT из Ethereum, Base, Polygon, Arbitrum и Optimism в `data/originals` и пишет опись в `data/archive.json`. Сайт от этого не меняется: в нём остаются только коллекции Ethereum.

```bash
npm run archive -- --dry            # показать, что пройдёт фильтр спама, ничего не скачивая
npm run archive -- --chain polygon  # только одна сеть
```

Спам отсеивается автоматически (суммы в названии, домены-однодневки, подделки под известные коллекции). Если что-то отфильтровалось зря или наоборот – контракт вписывается в `ARCHIVE_ALLOW` или `ARCHIVE_DENY` в `scripts/config.mjs`.

Файлы архива не синхронизируются и не попадают в репозиторий: это десятки гигабайт. На новом компьютере архив восстанавливается той же командой.

## Как обновить сайт после покупки новых NFT

```bash
npm run fetch && npm run derive && npm run build
git add -A && git commit -m "Обновить коллекцию" && git push
```

После `git push` GitHub сам пересоберёт и опубликует сайт за пару минут. Следить за сборкой: вкладка **Actions** в репозитории.

## Работа сразу на двух компьютерах

Главное правило: **репозиторий – основное хранилище, Proton Drive – удобство.**

- Перед работой: `git pull`
- После работы: `git add -A && git commit -m "..." && git push`
- Не редактируйте проект на двух компьютерах одновременно: синхронизация и git могут разойтись.

Если Proton Drive создал файлы-двойники вида `файл (1).astro` или `conflict`, удалите их и восстановите состояние из репозитория:

```bash
git status          # посмотреть, что изменилось
git checkout -- .   # вернуть файлы как в последнем коммите (правки пропадут)
```

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `Cannot find package 'astro'` или похожее | `npm install` |
| Ошибки после переноса папки между компьютерами | удалить `node_modules` и выполнить `npm install` заново: внутри лежат программы, собранные под конкретную систему |
| Порт 4321 занят | `npm run dev -- --port 4322` |
| Предупреждения `LF will be replaced by CRLF` | не ошибка, так и должно быть на Windows |
| `npm run fetch` ругается на 429 и часть картинок не скачалась | публичные шлюзы IPFS ограничивают частоту. Повторить позже, скрипт докачивает только недостающее |
| Сайт собрался, но картинок нет | выполнить `npm run derive` |
